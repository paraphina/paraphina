# Phase 5.1p Lighter Native Role Evidence Contract

Status: `HOLD`, non-live, nonfinancial evidence only.

This document defines the repo-owned Phase 5.1p Lighter native maker/taker role
join. It exists to prevent future agents from treating historical normalized
fills, post-only intent, fee assumptions, or strategy purpose as maker/taker
truth.

## Scope

Phase 5.1p is a quarantined offline evidence step:

- It may read raw Lighter native trade side identifiers inside the local
  process.
- It must not emit raw order IDs, client order IDs, venue order IDs, trade IDs,
  or raw native side IDs in board-facing artifacts.
- It must not place live orders, change strategy behavior, change risk limits,
  train models, authorize EV admission, or support financial claims.
- It feeds only the Phase 5.1n maker/taker recovery gate as
  `LIGHTER_TRADES_JSON` evidence when an exact canonical hash match exists.

## Join Formula

Inputs:

- Phase 5.1o native role source inventory labels.
- Canonical observed P_fill labels.
- Source P_fill labels referenced by canonical labels.
- Lighter native trade backfill runs with `account_index`, `is_maker_ask`,
  ask/bid account IDs, and ask/bid order/client side IDs.

For each canonical Lighter filled row with
`SOURCE_AVAILABLE_NO_CANONICAL_JOIN`:

1. Load the source P_fill labels referenced by `source_order_keys`.
2. Collect only hashed source identifiers: `order_id_hash` and
   `client_order_id_hash`.
3. Derive native maker/taker role from Lighter truth:
   account on ask side plus `is_maker_ask=true` means maker; account on ask side
   plus `is_maker_ask=false` means taker; account on bid side uses the inverse.
4. Hash Lighter native ask/bid side IDs and side client IDs inside quarantine.
5. Emit recovered evidence only if the canonical row has exactly `fill_count`
   unique native trade matches and all matched trades have known maker/taker
   roles.

All other outcomes remain `HOLD` with explicit status, such as
`NATIVE_ID_HASH_NO_MATCH`, `AMBIGUOUS_NATIVE_ID_HASH`,
`PARTIAL_NATIVE_ID_HASH_MATCH`, or `NATIVE_ROLE_INCOMPLETE`.

## Output Artifacts

Generated by `tools/phase51p_lighter_native_role_canonical_join.py`:

- `lighter_native_role_canonical_join_summary.json`
- `lighter_native_role_canonical_join_labels.jsonl`
- `lighter_native_role_evidence.jsonl`
- `evidence_pack/artifact_index.json`
- `manifest.json`

Allowed board-facing fields include:

- `canonical_group_id`
- `source_telemetry_sha256`
- `venue_id`
- `fill_count`
- `maker_taker_role_counts`
- `maker_taker_attribution_source`
- `native_role_source_status`
- `native_role_source_hold_reason`
- hashed native trade identifiers only, such as `native_trade_uid_hashes`

Forbidden board-facing fields include raw `order_id`, `client_order_id`,
`venue_order_id`, `ask_id`, `bid_id`, `ask_client_id`, `bid_client_id`, and
`trade_id`.
